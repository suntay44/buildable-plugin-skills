# UI Quality Playbook

Use this playbook when the app needs to feel polished, modern, and usable without becoming decorative.

## Core Principles

- Put the primary workflow on the first screen.
- Prefer clear hierarchy over visual effects.
- Use meaningful sample data that demonstrates real states.
- Keep controls visible near the data they affect.
- Use color for status, priority, selection, and risk.
- Avoid one-note palettes and generic gradients.
- Avoid marketing-page heroes inside product tools.

## Modern App Feel

- Use calm surfaces, clear spacing, and restrained borders.
- Keep cards compact; avoid cards inside cards.
- Use responsive grids with stable dimensions.
- Use icon buttons only when the icon is familiar or labeled.
- Keep destructive actions available but visually contained.
- Make empty states explain the next action.

## Typography

- Use one strong page title.
- Use compact section labels for dense tools.
- Keep body text readable and short.
- Do not use oversized hero text inside dashboards, task managers, CRM tools, or admin apps.

## Layout

- Mobile: stack the primary workflow first, then filters and supporting summaries.
- Desktop: use two-column layouts only when the secondary column helps the workflow.
- Keep filters close to the list/table they affect.
- Ensure text, controls, and badges do not overlap.

## Failure Modes

- generic placeholder UI
- impressive-looking but nonfunctional panels
- hidden core actions on mobile
- empty states that do not help recovery
- colors used only as decoration
- visually polished app with missing interaction states
